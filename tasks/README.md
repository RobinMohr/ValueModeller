# Task System

All tasks live in `tasks/` as JSON files with the naming convention: `[priority]_[id]_[kebab-title].json`

The `id` is a unique 8-character hex identifier assigned when the task is created. This ensures each task has a stable, unambiguous reference that AI agents can use to identify exactly which task they are working on.

## Default Template

Use `0_task_template.json` as the base for every new task. Copy it, rename it following the naming convention, and fill in the fields.

## Schema

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `id` | string | yes | Unique 8-char hex identifier (auto-generated by TecFactory) |
| `title` | string | yes | Short descriptive title |
| `priority` | number | yes | 1 = critical, 2 = high, 3 = medium, 4 = low |
| `type` | enum | yes | `"improvement"` \| `"problem"` \| `"idea"` |
| `state` | enum | yes | `"todo"` \| `"in-progress"` \| `"developed"` |
| `description` | string | yes | Detailed description of what needs to be done |
| `files` | string[] | yes | Relevant source file paths |
| `origin` | enum | yes | Who created the task (see below) |

## Origin Field

The `origin` field tracks how a task was created.

| Value | Meaning |
|-------|---------|
| `"user"` | Created manually by a human team member |
| `"ai"` | Created autonomously by an AI agent (e.g. QA agent) |
| `"user-assisted"` | Created by a human with AI assistance (e.g. user prompted AI to create it) |

## Naming Convention

- File format: `{priority}_{id}_{kebab-slug}.json`
- `priority` = priority number (1-4)
- `id` = unique 8-character hex identifier (e.g., `a1b2c3d4`)
- `kebab-slug` = kebab-case summary of the title (max 50 chars)
- Examples: `1_a1b2c3d4_fix-routing-bug.json`, `2_e5f6a7b8_add-edge-labels.json`
- The `0_task_template.json` file is the template and should not be picked up by agents as a real task (prefix `0_`).

## Why IDs?

IDs solve the problem of task identity:
- Agents can reference a specific task unambiguously (by filename or by `id` field)
- Renaming a task (changing priority) preserves its identity via the `id`
- No collisions between tasks with similar titles
